# 검토 체크리스트

변경에 해당하는 항목만 판정한다. 해당 없음은 `N/A`. S로 시작하는 항목의 UNVERIFIED는 BLOCKED 사유다.

## 안전 (S)

| ID | 항목 |
| --- | --- |
| S1 | 장비 connect·bringup·모터 구동·토크·캘리브레이션 쓰기·sudo를 테스트나 기본 실행 경로에 추가하지 않았다 |
| S2 | 중복 command ID·재전송·retained 메시지가 장비 재구동을 일으키지 않는다 |
| S3 | 만료·deadline 지난 명령과 과거 세션 결과를 실행하지 않는다 |
| S4 | 출발은 안착·두 팔 안전 복귀·Pinky 준비 확인 뒤에만 허가된다(관련 변경 시) |
| S5 | 명령 소유권을 옮기지 않았다: 관제=작업·출발 허가, OMX Host=양팔 구동·현장 정지, AI=action 후보만 |
| S6 | 통신 끊김·timeout·재시작 후 상태가 "결과 불명"으로 처리되고 성공으로 간주되지 않는다 |
| S7 | 실측/합의 전 값(timeout·도킹 오차·관절 제한·추론 deadline)을 임의 기본값으로 넣지 않았다 |

## 계약 (C)

| ID | 항목 |
| --- | --- |
| C1 | 생산자·소비자의 필드명·타입·필수 여부가 일치한다 |
| C2 | 단위·좌표계·frame·timestamp 기준이 명시되고 양쪽이 같다 |
| C3 | 전송 성공(HTTP 200, PUBACK, WSS 전송)을 업무 접수·장비 완료로 처리하지 않는다 |
| C4 | 운송 도착과 고객 수령을 별도 상태로 둔다 |
| C5 | 오류 응답 형식이 계약과 같고 소비자가 처리한다 |
| C6 | `/healthz` 성공을 연결·모델·장비 준비로 확대하지 않는다 |

## 변경 위생 (H)

| ID | 항목 |
| --- | --- |
| H1 | 소유 경로 밖 변경이 없거나 부모가 승인했다 |
| H2 | 새 의존성·lockfile 변경에 이유가 있다 |
| H3 | 비밀값·개인 환경 파일·모델 가중치·학습 데이터·빌드 산출물이 diff에 없다 |
| H4 | vendored 원본(lerobot, pinky_pro)을 고쳤다면 UPSTREAM 기록과 LICENSE를 보존했다 |
| H5 | 변경을 덮는 테스트가 있고 QA가 실제로 실행했다 |
