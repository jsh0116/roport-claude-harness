# 모듈 엔지니어 공통 규칙

모든 `*-engineer` 에이전트가 작업 시작 전에 읽는다. 분야별 내용은 각 에이전트 정의에 있다.

## 시작
1. 작업 패킷(작업 ID·소유 경로·계약 경로·완료 기준)과 루트·대상 모듈 `AGENTS.md`를 읽는다.
2. 계약(`_workspace/claude/02_architect_contract.md`)이 있으면 그대로 따른다. 없으면 직접 수정 요청으로 보고 변경 범위를 최소로 잡는다.
3. 첫 보고에 실제로 쓸 수 있는 도구 목록을 적는다.

## 수정 범위
- 소유 경로 안에서만 고친다. 공유 schema·lockfile·공용 설정·루트 파일은 부모(오케스트레이터)에게 요청한다.
- 다른 엔지니어가 같은 저장소에서 동시에 작업한다. 남의 변경을 되돌리거나 포맷하지 않는다.
- 새 의존성·추상화는 요청을 충족하는 데 꼭 필요할 때만 추가하고 이유를 보고한다.
- 커밋·push는 부모가 지시할 때만 한다.

## 장비·외부 시스템
- 장비 connect·bringup·실제 토픽 publish·모터 구동·토크·캘리브레이션 쓰기·sudo·펌웨어 작업을 실행하지 않는다.
- 실서비스 DB·Cloud 브로커·외부 API에 접속하는 테스트를 만들지 않는다. mock/replay/fixture로 검증한다.
- timeout·도킹 오차·관절 제한·deadline 같은 실측/합의 값이 계약에 `미정`이면 임의로 정하지 말고 부모에게 묻는다.

## 검증
- `.github/workflows/<module>-ci.yml`의 `run:` 명령을 `working-directory`에서 순서대로 실행한다.
- 도구 미설치·네트워크 차단은 `미실행: 사유`로 적고 통과로 쓰지 않는다. 단위·mock 통과를 실장비 검증으로 표현하지 않는다.

## 보고
`_workspace/claude/03_<agent>_report.md`에 작성하고 요약을 반환한다.

```
## 변경 파일
## 계약 반영 (항목 → 파일:줄)
## 실행한 검사 (명령 · 결과)
## 미실행·미해결·부모에게 요청
```

## 통신
- 부모에게서 `SendMessage`로 검토 지적(`_workspace/claude/04_*.md`)을 받으면 지적 항목만 고치고 보고서의 해당 절을 갱신한다.
- 계약 해석이 다른 엔지니어와 다르면 부모에게 알린다. 계약 변경은 부모가 확정한다.
